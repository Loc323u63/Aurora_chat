# Genius Lyrics в Aurora: архитектура, оптимизация и эксплуатация

> Документ относится к ветке `feature/genius-local-lyrics-import` форка `Loc323u63/Aurora_chat`.
> Это описание отдельной интеграции Genius и выполненного целевого прохода по её производительности. Оно не является заявлением, что каждый модуль Aurora прошёл полноценное профилирование.

## 1. Что добавлено

Интеграция позволяет искать песни через Genius API, получать адрес публичной страницы композиции и извлекать текст из HTML-страницы. Найденные тексты сохраняются локально и затем используются плеером как отдельный источник текстов песен.

LRCLIB, серверные тексты, Spotify и локальные LRC-файлы остаются самостоятельными источниками. Genius не заменяет их и участвует в поиске согласно порядку источников в настройках.

Основные возможности:

- поиск композиции по названию и исполнителю;
- проверка совпадения названия и основного исполнителя/участников;
- разбор только контейнеров `data-lyrics-container`, без комментариев и аннотаций;
- массовый импорт активной музыкальной библиотеки;
- локальное хранение текстов и статусов;
- возобновление прерванного импорта;
- последовательные запросы с паузой;
- остановка при HTTP 403, HTTP 429 или обнаруженной странице проверки доступа;
- подключение к существующему механизму `LyricsRepository` на Android и Desktop.

## 3. Как проходит поиск

1. Импортёр получает список песен из активной библиотеки через `MusicRepository.allLibrarySongs`.
2. Для каждой песни проверяется локальный статус. Уже сохранённые тексты и ранее зафиксированные `NOT_FOUND` повторно не запрашиваются.
3. Genius API получает поисковый запрос с названием и исполнителем. API используется для поиска и получения URL, а не как источник самого текста.
4. Кандидат проверяется по названию, исполнителю и домену URL. Переход на произвольный сайт не допускается.
5. Страница Genius разбирается Jsoup. Сохраняется только текст из контейнеров `data-lyrics-container`.
6. Текст и статус записываются в локальное хранилище.
7. `LyricsRepository` может вернуть локальный Genius-текст плееру, когда до него доходит очередь этого источника.

Genius возвращает обычный текст, поэтому такие строки не являются синхронизированными по времени. Для синхронизации нужны временные метки, которых парсер страницы не создаёт.

## 4. Локальное хранение

Тексты не записываются в Git-репозиторий и не включаются в исходный код приложения.

Для каждой песни создаётся отдельный UTF-8-файл с именем, вычисленным по SHA-256 от ID композиции:

```text
genius-lyrics/
    <sha256-song-id>.txt
    <sha256-song-id>.txt
    ...
```

Отдельно хранится индекс:

- `genius-lyrics-index.jsonl` — текущий журнал изменений;
- `genius-lyrics-index.json` — старый формат, который автоматически мигрируется при первом открытии новой версии.

В индексе находятся только ID песни, статус, URL Genius, сообщение об ошибке и время обновления. Сами тексты в индекс не помещаются. Хранилище и чтение индекса создаются лениво: обычный запуск Aurora не открывает журнал Genius, пока он действительно не понадобится.

### Журнал вместо постоянной перезаписи

Предыдущая реализация целиком сериализовала JSON-индекс при каждом изменении статуса. Во время импорта одна песня обычно получала как минимум две записи: `PENDING`, затем итоговый статус. При большой библиотеке это приводило к повторной записи уже существующих данных.

Теперь используется append-only JSONL:

- очередной статус дописывается одной строкой;
- при запуске восстанавливается последнее состояние для каждого ID;
- журнал пересобирается атомарно, когда содержит не менее 512 строк и число строк превышает число актуальных записей более чем в два раза;
- незавершённая последняя строка не склеивается со следующей записью;
- старый JSON-индекс мигрирует в новый формат без удаления уже сохранённых текстов.

Таким образом, обычная запись статуса не переписывает весь индекс. Полная компактизация выполняется только при накоплении устаревших записей.

Хранилище использует атомарную запись файлов текстов через общий механизм `persistBackupFileAtomically`. При сбое записи предыдущий файл не должен быть заменён неполным содержимым.

### Расположение

- Android: `noBackupFilesDir` приложения.
- Desktop: локальный каталог данных Aurora (`paths.local`).

Удаление или очистка данных приложения может удалить и локальные тексты. Отдельный экспорт Genius-текстов в этой версии не реализован.

## 5. Статусы и возобновление

| Статус | Значение | Что делает следующий запуск импорта |
| --- | --- | --- |
| `PENDING` | Импорт был начат, но не завершён | Повторяет запрос |
| `SUCCESS` | Текст сохранён | Пропускает, если файл существует |
| `NOT_FOUND` | Подходящая песня или контейнер с текстом не найдены | Пропускает, чтобы не повторять бесполезный запрос |
| `ERROR` | Сетевая или другая ошибка | Повторяет при следующем ручном запуске |
| `RATE_LIMITED` | Genius вернул HTTP 429 | Останавливает текущий импорт; следующая попытка — вручную |
| `BLOCKED` | HTTP 403 или страница проверки доступа | Останавливает текущий импорт; следующая попытка — вручную |

Повторный импорт не является автоматическим бесконечным циклом. Пользователь запускает его из настроек. Для временных ошибок и блокировок повторная попытка возможна при следующем запуске. `NOT_FOUND` намеренно пропускается, чтобы не отправлять одинаковые поисковые запросы снова и снова.

## 6. Оптимизации в этом проходе

### Диск и индекс

- Переход с полной перезаписи индекса на append-only JSONL уменьшает объём повторной работы при каждом сохранении статуса.
- Создание хранилища и чтение журнала отложены до первого обращения к Genius, чтобы не добавлять синхронную работу с диском в обычный запуск приложения.
- Компактизация выполняется не после каждой песни, а только при значительной доле устаревших записей.
- Тексты остаются отдельными файлами, поэтому импорт не собирает все тела песен в один большой объект или JSON-документ.
- Имя файла строится из SHA-256; hex-строка формируется через таблицу символов, без форматирования каждого байта через `String.format`.

### Сеть и память

- Для Genius-ответа установлен предел 2 MiB.
- Ограничение применяется и при отсутствии или недостоверности HTTP `Content-Length`: поток читается небольшими блоками и прекращается после превышения лимита.
- Поиск выполняется последовательно, с паузой 3 секунды между песнями.
- HTTP 403, 429 и обнаруженная CAPTCHA/страница проверки доступа останавливают импорт. Нет прокси-ротации, обхода CAPTCHA или маскировки запросов.

### Почему важна структура кода

Kotlin хорошо подходит для общей Android/Desktop-логики, но сам язык не устраняет лишние дисковые операции, повторные выделения памяти или блокировку главного потока. Поэтому оптимизация здесь направлена на конкретные затраты: частоту перезаписи индекса, чтение сетевого тела без известного размера, повторную компиляцию регулярных выражений и работу с файлами при старте приложения.

### Парсинг и строки

- Регулярные выражения нормализации, разделения исполнителей и обработки переносов строк создаются один раз, а не для каждой композиции.
- Проверка страницы на типовые признаки ограничения доступа не создаёт дополнительную полную копию HTML в нижнем регистре.
- Jsoup выбирает только контейнеры текста Genius; комментарии, стили и скрипты не сохраняются.

### Что не переписывалось без измерений

В других частях Aurora уже есть полезные механизмы производительности: раздельный поток позиции воспроизведения в `PlayerViewModel`, постраничная загрузка библиотеки, индексы локальной библиотеки, кэш обложек с ограничением размера, синхронизацией запросов и периодической очисткой. Я оставил эти подсистемы без рискованных изменений: оптимизация аудиопотока, USB-вывода или Compose-экранов без профиля нагрузки может дать обратный результат.

Это целевой оптимизационный проход по новой интеграции и связанным точкам подключения, а не подтверждённый benchmark всей Aurora. Численные показатели ускорения не заявляются: для них необходимо выполнить одинаковые замеры до и после на устройстве.

## 7. Настройка и использование

1. Создать приложение в Genius Developer и получить API access token.
2. Открыть в Aurora **Settings → Lyrics**.
3. Ввести токен Genius и сохранить его запуском импорта.
4. Нажать **Import lyrics for the whole library**.
5. Следить за количеством найденных текстов, пропусков, ошибок и объёмом локального хранилища.
6. При необходимости остановить импорт. При следующем ручном запуске он продолжит с песен, которым ещё требуется обработка.

Поле токена скрывает вводимые символы. Токен хранится в настройках и не является частью исходного кода. При экспорте резервной копии без учётных данных он исключается; при экспорте с учётными данными настройки включаются в резервную копию.

В интерфейсе отображается объём файлов текстов. Размер небольшого индекса в эту цифру не включён.

## 8. Ограничения и осторожность

- API Genius используется для поиска и метаданных; текст извлекается со страницы Genius.
- Автоматическое извлечение текста может противоречить условиям Genius. Наличие API-токена не означает, что парсинг страниц разрешён. Перед использованием следует самостоятельно ознакомиться с актуальными условиями Genius.
- Импорт не пытается преодолевать блокировки и ограничения доступа.
- Результаты Genius в этой реализации не синхронизированы по времени.
- Сопоставление по названию и исполнителю снижает риск неправильного результата, но не исключает его полностью. Разные версии, ремиксы и одноимённые песни требуют проверки.
- Содержимое текстов хранится локально и не отправляется в репозиторий, но сам факт поиска передаёт Genius название и исполнителя песни.

## 9. Проверка сборки и тестов

Требования проекта см. в основном `README.md`: JDK 21, Android SDK 35, NDK 27.0.12077973 и CMake 3.22.1.

Из корня репозитория:

```bash
# Тесты общей Kotlin-логики
./gradlew :core:test

# Сборка Android debug APK
./gradlew :app:assembleDebug

# Тесты Desktop
./gradlew :desktop:test
```

На Windows используется `gradlew.bat`.

Новые тесты в `GeniusLyricsTest.kt` проверяют:

- извлечение только контейнеров Genius и сохранение переносов строк;
- сохранение и повторное открытие локальных текстов;
- подключение Genius как независимого источника;
- компактизацию журнала повторных статусов;
- восстановление после оборванной последней строки;
- миграцию старого JSON-индекса;
- отклонение HTTP-ответа, который превышает лимит чтения;
- отсутствие создания каталога Genius при обычной инициализации хранилища.

**Важно:** изменения в этой ветке были сохранены через GitHub API. Полноценная Gradle-сборка и выполнение тестов в этой среде не запускались. До использования на основном устройстве сначала выполните команды выше и проверьте результат сборки.
